# 11 · 多模态 (Multimodal)

> 对应目录：`vllm/multimodal/`

## 什么是多模态

普通 LLM 只吃文字。多模态模型能同时理解**图片、音频、视频**等。比如你发一张图问"这是什么"，模型能看图回答。

类比：从"只会读字的助手"升级成"能看图能听音的助手"。

## 核心挑战：把非文字变成模型能懂的东西

模型内部只认 token（数字）。所以多模态的核心问题是：**怎么把一张图片变成模型能处理的形式？**

流程大致是：

```
图片
  ↓ 图像编码器（如 ViT）
图像特征向量（embeddings）
  ↓ 投影/对齐
和文本 token 拼在一起
  ↓
喂给语言模型
```

文字和图片最终被拼成一个统一的序列，模型一视同仁地处理。

## 占位符机制

一个关键技巧：在文本里用**占位符 token** 标记图片的位置。

```
文本: "这张图 <image> 里有什么？"
              ↑
        这里会被替换成图片的特征向量
```

模型处理时，`<image>` 这个占位符的位置被实际的图像特征填充。一张高清图可能占成百上千个占位符 token（因为信息量大）。

## 代码结构

| 文件/目录 | 作用 |
|-----------|------|
| `multimodal/registry.py` | 多模态注册表，管理各模型的处理逻辑 |
| `multimodal/processing.py` | 预处理：把图片/音频转成模型输入 |
| `multimodal/inputs.py` | 多模态输入的数据结构 |
| `multimodal/profiling.py` | 显存规划（多模态输入很占显存） |

## 多模态怎么融入主流程

回顾前面的请求生命周期，多模态主要影响**输入处理**和**编码**两步：

1. **输入处理**（在 `LLMEngine.add_request` 里）：图片被预处理，文本里插入占位符
2. **编码**（在 worker 里）：图像编码器先把图片转成特征，缓存到 encoder cache
3. 之后的调度、KV Cache、采样和纯文本基本一致

调度器里有个 `encoder_cache_manager`（`v1/core/encoder_cache_manager.py`），专门管理编码后的图像特征缓存——因为这部分也很占显存，需要和 KV Cache 类似地管理。

## 怎么用

```python
from vllm import LLM
from vllm.assets.image import ImageAsset

llm = LLM(model="llava-hf/llava-1.5-7b-hf")

outputs = llm.generate({
    "prompt": "USER: <image>\n这是什么？\nASSISTANT:",
    "multi_modal_data": {"image": ImageAsset("stop_sign").pil_image},
})
```

## 为什么多模态更耗显存

一张图等于成百上千个 token，且图像特征本身也要缓存。所以多模态服务的并发能力通常低于纯文本。`multimodal/profiling.py` 就是在启动时估算这部分开销，合理规划显存。

## 小结

- 多模态 = 让模型能处理图片/音频/视频，不只是文字
- 核心：用编码器把图片转成特征，通过占位符插入文本序列
- 主要影响输入处理和编码两步，后续流程与文本基本一致
- 比纯文本更耗显存，有专门的 encoder cache 管理
