# 35 · 语音转文本 (Speech-to-Text)

> 对应目录：`vllm/entrypoints/speech_to_text/`、`vllm/entrypoints/openai/speech_to_text/`

## 这个模块负责什么

支持**语音识别**类模型（如 Whisper），把音频转成文字。提供 OpenAI 兼容的转录（transcription）和翻译（translation）接口。

类比：这是 `11-多模态.md` 的"音频版"——输入从图片换成音频，输出是文字。

## 支持的能力

| 能力 | 对应 OpenAI 端点 | 说明 |
|------|-----------------|------|
| 转录 (transcription) | `/v1/audio/transcriptions` | 音频 → 同语言文字 |
| 翻译 (translation) | `/v1/audio/translations` | 音频 → 英文文字 |

## 这类模型的结构：Encoder-Decoder

语音模型（如 Whisper）通常是 **编码器-解码器（encoder-decoder）** 结构，和纯文本的 decoder-only 模型不同：

```
音频
  ↓ 音频编码器（encoder）：把声音波形转成特征
音频特征
  ↓ 文本解码器（decoder）：基于音频特征逐字生成文字
"今天天气很好"
```

- Encoder 处理音频（一次性）
- Decoder 像普通 LLM 一样逐 token 生成文字，但生成时会"参考"音频特征（cross-attention）

## 在 vLLM 里怎么跑

复用核心引擎的能力：

1. **音频预处理**：把上传的音频文件转成模型输入的特征（梅尔频谱等）
2. **编码**：音频编码器处理，结果作为 decoder 的条件
3. **解码**：decoder 逐字生成文字（走 `01~07` 的生成流程，但带音频条件）
4. **输出**：detokenize 成文字（见 `18`）

回顾 `02-引擎.md` 提到的 "encoder-decoder 模型"特殊处理、`05-Worker模型执行.md` 里的 `is_encoder_decoder` 判断——就是在适配这类模型。

## 代码结构

| 目录 | 作用 |
|------|------|
| `entrypoints/speech_to_text/` | 语音转文本的核心逻辑（音频处理、分块） |
| `entrypoints/openai/speech_to_text/` | OpenAI 兼容的 HTTP 接口 |

## 长音频分块

音频可能很长（几十分钟）。模型一次能处理的音频长度有限（Whisper 通常是 30 秒一段）。所以长音频会被**切成多段**分别转录，再把结果拼接。这部分逻辑在 `speech_to_text/` 里处理。

## 怎么用

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="x")

with open("audio.mp3", "rb") as f:
    result = client.audio.transcriptions.create(
        model="openai/whisper-large-v3",
        file=f,
    )
print(result.text)
```

启动：`vllm serve openai/whisper-large-v3`

## 对新手的意义

- 这是 vLLM 在"文本生成"之外的又一类任务支持，说明它是通用推理引擎
- 理解"encoder-decoder 结构 + 音频作为条件"即可
- 用法和 OpenAI 的音频接口完全一致，迁移零成本

## 小结

- 支持 Whisper 等语音识别模型，做转录和翻译
- 这类模型是 encoder-decoder 结构：编码器处理音频，解码器逐字生成文字
- 复用核心引擎的生成流程，额外处理音频预处理和长音频分块
- 提供 OpenAI 兼容的 `/v1/audio/*` 端点
