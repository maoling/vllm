# 27 · 核心数据结构

> 对应文件：`vllm/sampling_params.py`、`vllm/v1/request.py`、`vllm/outputs.py`、`vllm/sequence.py`、`vllm/inputs/`

## 为什么单独讲数据结构

读源码时，与其追每个函数，不如先认清"在各模块间流动的核心对象长什么样"。理解了这些数据结构，整个流程就像看懂了"在传递什么包裹"。

类比 Web 后端：这些就是贯穿系统的 DTO / 实体类。

## 一张图：数据结构的流转

```
用户输入
  ↓
PromptType / EngineInput   （输入：prompt + 多模态数据）
  +
SamplingParams             （怎么生成的参数）
  ↓ 进入引擎
Request                    （引擎内部的请求对象，带状态）
  ↓ 每步 step 产出
EngineCoreOutput           （引擎核心的原始输出：新 token）
  ↓ 后处理
RequestOutput              （返回给用户的最终结果）
```

## 1. SamplingParams —— 怎么生成

`vllm/sampling_params.py`。控制生成行为的所有旋钮（详见 `06-采样.md`）：

```python
SamplingParams(
    temperature=0.7,      # 随机性
    top_p=0.9,            # 核采样
    max_tokens=100,       # 最多生成多少
    stop=["\n\n"],        # 停止词
    n=1,                  # 生成几个候选
)
```

它从用户请求一路传到采样阶段，是"生成意图"的载体。

## 2. 输入：PromptType / EngineInput

`vllm/inputs/`。表示"输入是什么"。可以是：

- 纯文本字符串：`"你好"`
- 已经 tokenize 的 token id：`{"prompt_token_ids": [108386]}`
- 带多模态：`{"prompt": "...", "multi_modal_data": {"image": ...}}`

输入处理器（`input_processor`）会把这些统一规整成引擎能处理的形式（回顾 `02-引擎.md` 的 `add_request`）。

## 3. Request —— 引擎内部的请求对象

`vllm/v1/request.py`。这是引擎内部最核心的对象，代表"一个正在处理的请求"，带着完整状态：

| 字段（概念） | 含义 |
|------|------|
| `request_id` | 唯一标识 |
| `prompt_token_ids` | 输入的 token |
| `num_computed_tokens` | 已经算了多少 token（见 `03` 调度核心） |
| `num_tokens` | 总共需要算多少 |
| `output_token_ids` | 已经生成的 token |
| `status` | 状态（waiting / running / finished…） |
| `sampling_params` | 采样参数 |
| `block_hashes` | 用于前缀缓存（见 `16`） |

调度器（`03`）、KV Cache（`04`）、worker（`05`）都围着这个对象转。回顾调度器里满屏的 `request.num_computed_tokens`、`request.status`——操作的就是它。

### 请求的状态机

```
WAITING（排队）
  ↓ 被调度
RUNNING（生成中）
  ↓ 显存不够
PREEMPTED（被抢占，回到等待）
  ↓ 完成
FINISHED（结束：EOS / 达到 max_tokens / 停止词）
```

## 4. 输出：EngineCoreOutput → RequestOutput

- `EngineCoreOutput`（`v1` 内部）：引擎核心每步吐出的原始结果，主要是"新生成的 token id"
- `RequestOutput`（`vllm/outputs.py`）：经过 detokenize、组装后，返回给用户的成品

```python
RequestOutput(
    request_id="...",
    prompt="你好",
    outputs=[CompletionOutput(
        text="你好！有什么可以帮你的吗？",   # detokenize 后的文字
        token_ids=[...],
        finish_reason="stop",               # 为什么结束
    )],
    finished=True,
)
```

用户拿到的 `outputs[0].outputs[0].text` 就来自这里。

## 5. sequence.py —— 兼容/通用序列结构

`vllm/sequence.py` 里有一些跨版本通用的序列相关结构。v1 引擎主要用 `v1/request.py` 的 `Request`，但部分通用定义仍在这里。新手了解"序列 = 一个请求的 token 流"这个概念即可。

## 串起来看（呼应 07-请求生命周期）

```
"你好"(PromptType) + SamplingParams
   ↓ add_request：规整 + tokenize
Request（status=WAITING, num_computed=0）
   ↓ 调度 → 执行 → 采样 → 更新（每步循环）
Request（output_token_ids 不断增长，num_computed 追上 num_tokens）
   ↓ 完成（status=FINISHED）
EngineCoreOutput → detokenize → RequestOutput
   ↓
用户拿到 .text
```

## 小结

- 认清核心数据结构 = 看懂"模块间在传什么"
- `SamplingParams`：生成参数；`PromptType`：输入
- `Request`：引擎内部请求对象，带状态机，是调度/缓存/执行的中心
- `RequestOutput`：返回用户的成品（含 text、finish_reason）
- 配合 `07-请求生命周期.md` 一起看，能把"流程"和"数据"对应起来
