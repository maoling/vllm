# 43 · 异步引擎与在线服务 (AsyncLLM)

> 对应文件：`vllm/v1/engine/async_llm.py`、`vllm/engine/protocol.py`

## 同步 vs 异步：两种引擎

前面 `02-引擎.md` 讲的 `LLMEngine` 是**同步**的：你调 `step()`，它跑一步，返回。适合离线批处理（`LLM` 类）。

但在线 HTTP 服务（`vllm serve`）不一样——它要**同时处理很多并发连接**，每个连接还要流式返回。这时需要**异步**引擎 `AsyncLLM`。

类比 Web 后端：`LLMEngine` 像同步阻塞式处理，`AsyncLLM` 像基于事件循环的异步处理（类似 Java 的 Netty/Reactor、Python 的 asyncio）。

## 为什么在线服务必须异步

设想 100 个用户同时连进来，每人要流式接收生成的文字。如果用同步模型，处理一个就阻塞其他的，根本扛不住。

异步的做法：用 Python 的 `asyncio` 事件循环，让"等待 GPU 计算"、"等待网络发送"这些 IO 等待不阻塞其他请求。引擎在后台不停 `step()`，每产出 token 就推送给对应的连接。

```
asyncio 事件循环
  ├─ 用户A 的协程：await 下一个 token → 推送
  ├─ 用户B 的协程：await 下一个 token → 推送
  └─ 后台引擎循环：不停 step()，产出 token 分发给各协程
```

## AsyncLLM 的核心：每个请求一个异步流

用户调用 `generate()` 得到的是一个**异步生成器（async generator）**，可以 `async for` 逐 token 拿结果：

```python
async for output in async_llm.generate(prompt, sampling_params, request_id):
    # 每次拿到新生成的内容，立刻推送给 HTTP 连接（SSE）
    yield output
```

这正好对接 `23-OpenAI兼容API服务.md` 的流式响应（SSE）：引擎吐一个 token，API 层就推一个 `data:` 事件给客户端。

## 进程架构：前后台分离

回顾 `02-引擎.md` 提到的 `EngineCore` 跑在独立进程。`AsyncLLM` 把这个发挥到极致：

```
主进程（asyncio）：
  · 处理 HTTP 连接
  · tokenize / detokenize（见 18）
  · 通过 IPC 和 EngineCore 进程通信
        ↕ 进程间通信（输入请求 / 输出 token）
EngineCore 进程：
  · 专心跑 GPU 计算循环（schedule → execute → sample）
```

好处：CPU 密集的文本处理（在主进程）和 GPU 计算（在 EngineCore 进程）并行，互不阻塞。`core_client.py` 就是主进程和 EngineCore 通信的客户端。

## 请求怎么流转

```
HTTP 请求到达（FastAPI，异步）
  ↓ AsyncLLM.generate() 创建一个请求 + 输出队列
  ↓ 把请求经 IPC 发给 EngineCore 进程
  ↓ EngineCore 把它纳入调度，每步产出 token
  ↓ token 经 IPC 回传，detokenize，放入该请求的输出队列
  ↓ async for 从队列取出，SSE 推送给客户端
请求完成 → 关闭流
```

## 关键组件

| 文件/概念 | 作用 |
|-----------|------|
| `v1/engine/async_llm.py` | `AsyncLLM` 主类，异步接口 |
| `v1/engine/core_client.py` | 与 EngineCore 进程通信的客户端 |
| `v1/engine/output_processor.py` | 把引擎输出分发到各请求的流 |
| `engine/protocol.py` | 引擎客户端的抽象协议 |

## 取消与中止

在线服务里，用户可能中途断开连接。异步引擎要能感知并**中止**那个请求，释放它的 KV Cache（回顾 `03` 的 `abort`、`finish_requests`）。否则断开的请求还在白白占用 GPU。这是在线服务相比离线批处理多出来的重要处理。

## 对新手的意义

- 离线用 `LLM`（同步），在线服务用 `AsyncLLM`（异步），底层共用同一个 EngineCore
- 理解"异步是为了高并发流式服务"这个动机最关键
- 你的 Web 异步经验（事件循环、协程、背压）直接适用

## 小结

- `AsyncLLM` 是为在线高并发流式服务设计的异步引擎，基于 asyncio
- 每个请求是一个异步流，`async for` 逐 token 拿结果，对接 SSE
- 前后台进程分离：主进程做 IO/文本处理，EngineCore 进程专注 GPU
- 要处理请求中止（用户断连），及时释放资源
- 和同步 `LLMEngine` 共享核心，区别在并发模型
