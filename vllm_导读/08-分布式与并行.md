# 08 · 分布式与并行 (Distributed)

> 对应目录：`vllm/distributed/`

## 为什么需要分布式

一块 GPU 装不下一个大模型，或者装得下但跑得慢。比如 700 亿参数的模型，光权重就要约 140GB（FP16），单卡放不下。解决办法：**把模型/计算拆到多块 GPU 上**。

类比 Web 后端：单机扛不住就上集群。但这里更复杂——不是简单地复制多份，而是把"一个模型"切开协同计算。

## 三种并行方式

vLLM 支持三种并行，可以组合使用。

### 1. 张量并行 (Tensor Parallelism, TP)

把**单个层内的大矩阵**横切/竖切到多卡，每张卡算一部分，再合并结果。

```
一个大矩阵乘法 (8192 x 8192)
  ├─ GPU0 算左半
  └─ GPU1 算右半
  → 合并（需要卡间通信 all-reduce）
```

- 特点：每一层都需要卡间通信，对带宽要求高（通常用 NVLink）
- 适合：单机多卡
- 配置：`tensor_parallel_size=2`

### 2. 流水线并行 (Pipeline Parallelism, PP)

把模型**按层切段**，不同卡负责不同的层。

```
GPU0: 第 1~20 层
GPU1: 第 21~40 层
数据像流水线一样：GPU0 算完交给 GPU1
```

- 特点：通信少（只在切分点传递），但有"流水线气泡"（启动/排空时有空闲）
- 适合：跨多机
- 配置：`pipeline_parallel_size=2`

### 3. 数据并行 (Data Parallelism, DP)

把**整个模型复制多份**，每份独立处理不同的请求。

- 特点：没有卡间协同计算，纯粹分摊请求量
- 适合：模型能放进单卡，想提高吞吐
- 配置：`data_parallel_size=2`

## 组合使用

实际部署常组合，比如 `TP=8, PP=2` 表示用 16 张卡：每 8 张做张量并行组成一个"完整模型副本"，2 组用流水线并行串起来。

## 关键文件

| 文件/目录 | 作用 |
|-----------|------|
| `distributed/parallel_state.py` | 并行状态管理，定义各种通信组（TP组、PP组等） |
| `distributed/communication_op.py` | 通信原语（all-reduce、all-gather 等） |
| `distributed/device_communicators/` | 不同硬件的通信后端（NCCL、自定义 all-reduce 等） |
| `distributed/kv_transfer/` | KV Cache 跨节点传输（用于 PD 分离） |

## 通信原语（借 MPI 概念）

多卡协同靠几个基本通信操作，理解这几个就够了：

| 操作 | 含义 | 用在哪 |
|------|------|--------|
| all-reduce | 所有卡的数据相加，结果广播回所有卡 | 张量并行合并结果 |
| all-gather | 收集所有卡的数据拼到一起 | 收集分片输出 |
| broadcast | 一张卡把数据发给所有卡 | 同步输入 |
| send/recv | 点对点传输 | 流水线并行传递中间结果 |

这些底层用 NVIDIA 的 NCCL 库实现，vLLM 也有自己优化的 custom all-reduce（`csrc/custom_all_reduce.cuh`）。

## 进阶：PD 分离 (Prefill-Decode Disaggregation)

一个较新的架构思路：prefill（处理 prompt，计算密集）和 decode（逐字生成，访存密集）特性不同，把它们放到不同的 GPU 池子上，各自优化。它们之间需要传递 KV Cache，这就是 `distributed/kv_transfer/` 的用途。

## 小结

- 单卡放不下/跑不快大模型 → 多卡并行
- 三种方式：张量并行（切层内矩阵）、流水线并行（切层）、数据并行（复制模型）
- 靠 all-reduce 等通信原语协同，底层用 NCCL
- 这是把 vLLM 从"单卡玩具"变成"生产级集群"的关键
