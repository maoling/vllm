# 19 · 配置系统 (Config)

> 对应目录：`vllm/config/`、`vllm/engine/arg_utils.py`

## 这个模块负责什么

把"用户的各种设置"组织成结构化的配置对象，贯穿整个系统。模型是什么、用几张卡、KV Cache 多大、用不用量化……全在这里定义。

类比 Web 后端：这就是 `application.yml` / 配置中心，只不过是强类型的 Python 对象。

## 为什么值得单独了解

配置是理解 vLLM 行为的"总开关"。看懂配置，就知道一个 vLLM 实例到底在怎么跑。而且各模块（调度器、KV Cache、worker）初始化时都从配置读参数，是串联全局的线索。

## 顶层配置：VllmConfig

`config/vllm.py` 里的 `VllmConfig` 是总配置，聚合了一堆子配置：

```python
VllmConfig
├── model_config        模型相关（路径、数据类型、最大长度…）→ config/model.py
├── cache_config        KV Cache 相关（块大小、显存占比…） → config/cache.py
├── parallel_config     并行相关（TP/PP/DP 大小）         → config/parallel.py
├── scheduler_config    调度相关（最大 batch、策略…）      → config/scheduler.py
├── lora_config         LoRA 相关                         → config/lora.py
├── quant_config        量化相关                          → config/quantization.py
├── speculative_config  推测解码相关                      → config/speculative.py
├── compilation_config  编译优化相关                      → config/compilation.py
└── ...                 还有多模态、结构化输出等
```

每个子配置对应前面导读里的一个模块。这是一张很好的"模块清单"。

## 从命令行到配置对象

用户可以从命令行传参：

```bash
vllm serve meta-llama/Llama-3-8B \
    --tensor-parallel-size 2 \
    --max-model-len 4096 \
    --gpu-memory-utilization 0.9
```

`engine/arg_utils.py` 里的 `EngineArgs` 负责把这些命令行参数解析、校验，再转换成上面的 `VllmConfig`。

```
命令行参数 / Python 参数
  ↓ EngineArgs（解析 + 校验 + 设默认值）
VllmConfig（结构化配置对象）
  ↓ 传给引擎和各组件
```

## 几个新手最常调的参数

| 参数 | 作用 | 直觉 |
|------|------|------|
| `model` | 模型路径/名字 | 用哪个模型 |
| `tensor_parallel_size` | 张量并行卡数 | 用几张卡拆模型 |
| `max_model_len` | 最大上下文长度 | 一个请求最多多少 token |
| `gpu_memory_utilization` | 显存占用比例（默认 0.9） | 留多少显存给 KV Cache |
| `max_num_seqs` | 最大并发请求数 | 一个 batch 最多几个请求 |
| `dtype` | 数据类型（fp16/bf16…） | 权重精度 |
| `quantization` | 量化方法 | 见 09-量化.md |

> 调参经验：`gpu_memory_utilization` 调高能容纳更多并发，但太高可能 OOM；`max_model_len` 设太大会占用更多 KV Cache 显存，减少并发能力。这俩是吞吐/容量权衡的关键旋钮。

## 配置如何影响各模块

举几个例子，体会配置的串联作用：

- `cache_config.gpu_memory_utilization` → 决定 KV Cache 能切多少块 → 决定最大并发（见 `04`）
- `scheduler_config.max_num_batched_tokens` → 调度器每步的 token 预算（见 `03`）
- `parallel_config.tensor_parallel_size` → worker 怎么切分模型到多卡（见 `08`）

## 小结

- 配置系统把所有设置组织成结构化对象 `VllmConfig`
- 它聚合的子配置，正好对应各个功能模块，是一张模块地图
- `EngineArgs` 负责把命令行/参数转成 `VllmConfig`
- 看懂配置 = 看懂一个 vLLM 实例怎么跑；几个关键旋钮控制吞吐与容量
