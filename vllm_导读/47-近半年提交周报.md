## 四、主线复盘

### 4.1 Model Runner V2 的灰度路径（教科书级的渐进迁移）

```
2026-05-14  Qwen3 dense 模型默认启用        ← 单一模型试点
2026-05-18  有 KV connector 时回退 V1       ← 风险隔离
2026-06-16  GraniteMOE 默认启用
2026-06-18  量化模型默认启用                ← 扩大覆盖
2026-08-18  pooling 模型默认启用
2026-08-27  全部模型默认启用                ← 收官
2026-10-09  移除 ROCm 的 MRV1 例外           ← 清理退路
```

这条路径值得学习：**先单点试点 → 风险隔离回退 → 按模型类别逐步扩大 → 全量默认 → 清理旧路径**。期间伴随大量 `[Bugfix][MRV2]` 提交（CUDA graph 捕获、LoRA warmup、logprob dtype、int32 溢出等），说明灰度期的问题暴露充分。

### 4.2 Rust 前端的建设节奏

5 月落地骨架后，6-10 月持续以 207 条提交补齐能力，顺序大致是：

1. **基础端点**：`/version`、`/server_info`、`/get_world_size`、`/abort_requests`、`/v1/models`
2. **Parser 生态**：hy_v3、InternLM2、Phi-4、Granite4、Gemma4 → 最终统一为 **unified parser 接口**（#46583）
3. **参数校验对齐 Python**：越界 token、`max_logprobs`、`bad_words`、`min_tokens`
4. **进阶能力**：动态 LoRA、流式 generate、CORS、结构化工具调用（xgrammar-structural-tag）、thinking_token_budget
5. **性能**：专用运行时隔离 HTTP/ZMQ（#46051）、tool parser 扫描复杂度优化

对应导读 `23`（API 服务）与 `39`（工具调用）。

### 4.3 性能工作的两种形态
