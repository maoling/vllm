# 09 · 量化 (Quantization)

> 对应目录：`vllm/model_executor/layers/quantization/`、`csrc/quantization/`

## 什么是量化

模型权重默认用 16 位浮点数（FP16）存储。量化就是用**更少的位数**（如 8 位、4 位整数）来表示权重和/或激活值。

类比：把一张高清图片压缩成小图。体积小了很多，画质（精度）损失一点点，但大部分场景够用。

## 为什么要量化

| 好处 | 说明 |
|------|------|
| 省显存 | FP16 → INT4，权重体积缩到约 1/4，单卡能放下更大模型 |
| 更快 | 数据量小，访存更快；低精度计算吞吐更高 |
| 降成本 | 同样的卡能服务更多请求 |

代价：精度略有损失，可能让输出质量轻微下降。好的量化方法能把损失控制得很小。

## 常见量化方法

vLLM 支持很多种，新手了解这几个主流的即可：

| 方法 | 位数 | 特点 |
|------|------|------|
| GPTQ | 4-bit | 训练后量化，精度保持较好，社区模型多 |
| AWQ | 4-bit | 激活感知量化，速度快 |
| FP8 | 8-bit 浮点 | 新硬件（H100 等）原生支持，精度损失极小 |
| INT8 | 8-bit 整数 | 通用，兼容性好 |
| bitsandbytes | 4/8-bit | 易用，加载方便 |

## 怎么用

加载已经量化好的模型时，vLLM 通常能自动识别；也可以显式指定：

```python
llm = LLM(model="TheBloke/Llama-2-7B-GPTQ", quantization="gptq")
```

## 代码结构

```
model_executor/layers/quantization/
├── __init__.py          ← 量化方法注册表
├── gptq.py              ← GPTQ 实现
├── awq.py               ← AWQ 实现
├── fp8.py               ← FP8 实现
└── ...                  ← 其他方法
```

每种方法实现一套统一的接口（量化的线性层），告诉模型：
- 权重怎么存（用什么格式打包）
- forward 时怎么解包并计算

真正的低精度矩阵乘法 kernel 在 `csrc/quantization/` 里用 CUDA 实现。

## 核心抽象：QuantizationConfig

每种量化方法都有一个配置类，决定如何替换模型里的普通线性层为量化线性层。模型加载时，框架根据配置把 `nn.Linear` 换成对应的量化版本（比如 `GPTQLinear`）。

这是一个典型的**策略模式**：模型结构不变，只是把"计算线性层"这步的实现换成量化版。

## 直觉理解精度与位数

```
FP16:  每个权重 16 位 → 精度高，占空间大
FP8 :  每个权重 8 位  → 精度略降，省一半
INT4:  每个权重 4 位  → 精度更低，省 3/4
```

实践经验：8-bit 几乎无损，4-bit 在多数任务上也可接受。选哪种是"显存/速度 vs 质量"的权衡。

## 小结

- 量化 = 用更少位数表示权重，省显存、提速
- 主流方法：GPTQ、AWQ（4-bit），FP8、INT8（8-bit）
- 代码在 `quantization/`（Python 接口）+ `csrc/quantization/`（CUDA kernel）
- 本质是策略模式：把普通线性层替换成量化线性层
