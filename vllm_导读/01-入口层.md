# 01 · 入口层 (Entrypoints)

> 对应目录：`vllm/entrypoints/`

## 这个模块负责什么

入口层是用户和 vLLM 打交道的"门面"。它接收用户请求，做预处理，然后交给引擎。

类比 Web 后端：这就是 **Controller 层 + 请求解析过滤器**。

## 两种使用方式

vLLM 有两个主要入口：

### 1. 离线推理（直接调用）

```python
from vllm import LLM, SamplingParams

llm = LLM(model="meta-llama/Llama-3-8B")
outputs = llm.generate(["你好"], SamplingParams(max_tokens=100))
print(outputs[0].outputs[0].text)
```

对应代码：`vllm/entrypoints/llm.py` 里的 `LLM` 类。

适合：批量处理、脚本、实验。

### 2. 在线服务（HTTP API）

```bash
vllm serve meta-llama/Llama-3-8B
```

然后像调用 OpenAI 一样发 HTTP 请求。对应代码：`vllm/entrypoints/openai/api_server.py`（基于 FastAPI）。

适合：生产部署、对外提供服务。

## 关键文件

| 文件 | 作用 |
|------|------|
| `entrypoints/llm.py` | `LLM` 类，离线推理入口 |
| `entrypoints/openai/api_server.py` | FastAPI HTTP 服务器 |
| `entrypoints/chat_utils.py` | 聊天模板处理（把对话格式化成模型输入） |
| `entrypoints/offline_utils.py` | 离线推理的辅助逻辑（请求注册、引擎循环） |

## 核心流程：generate() 做了什么

看 `LLM.generate()`（`llm.py` 第 422 行附近）：

```python
def generate(self, prompts, sampling_params, ...):
    # 实际委托给 _run_completion
    return self._run_completion(prompts=prompts, params=sampling_params, ...)
```

`_run_completion`（在 `offline_utils.py`）做两步：

```python
def _run_completion(self, prompts, params, ...):
    # 第一步：把所有 prompt 注册到引擎
    self._add_completion_requests(prompts=prompts, params=params, ...)
    # 第二步：反复 step() 直到全部完成
    return self._run_engine(output_type, use_tqdm=use_tqdm)
```

而 `_run_engine` 的核心就是一个循环：

```python
def _run_engine(self, ...):
    outputs = []
    while self.llm_engine.has_unfinished_requests():
        step_outputs = self.llm_engine.step()   # 推进一步
        for output in step_outputs:
            if output.finished:
                outputs.append(output)
    return outputs
```

> 关键理解：用户调一次 `generate()`，内部其实是不断调 `engine.step()`，每一步生成一小批 token，直到所有请求都生成完毕。

## 一次请求注册做了什么

`_add_request`（`offline_utils.py`）最终调到 `LLMEngine.add_request()`：

```python
def _add_request(self, prompt, params, ...):
    request_id = str(next(self.request_counter))   # 分配唯一 ID
    return self.llm_engine.add_request(request_id, prompt, params, ...)
```

引擎内部会把 prompt 文本 tokenize 成 token id 列表，构造成一个内部请求对象。

## 小结

- 入口层 = 门面，负责接收请求 + 预处理 + 启动引擎循环
- 两个入口：`LLM` 类（离线） 和 `api_server`（在线 HTTP）
- 核心套路：`add_request()` 注册请求 → 循环 `step()` 推进 → 收集完成的输出
- 下一站：请求被交给**引擎**（见 `02-引擎.md`）
