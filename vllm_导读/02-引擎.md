# 02 · 引擎 (Engine)

> 对应目录：`vllm/v1/engine/`

## 这个模块负责什么

引擎是 vLLM 的"大脑"，负责协调全局：接收请求 → 调度 → 执行 → 处理输出。

类比 Web 后端：这是 **Servlet 容器 / 应用主控**，把各个组件串起来。

> 注：vLLM 有新旧两代引擎。旧的在 `vllm/engine/`，新的（当前主力）在 `vllm/v1/engine/`。本文只讲 v1。

## 两个层次的引擎

新手容易混淆，这里说清楚有两个类：

| 类 | 文件 | 角色 |
|----|------|------|
| `LLMEngine` | `v1/engine/llm_engine.py` | 外层封装，对接入口层 |
| `EngineCore` | `v1/engine/core.py` | 内层核心，真正的引擎循环 |

可以理解为：`LLMEngine` 是"前台经理"（对外接待），`EngineCore` 是"后厨主管"（真正干活）。

## LLMEngine：对外的封装

它有两个最重要的方法。

### add_request() —— 接收请求

`llm_engine.py` 第 218 行附近：

```python
def add_request(self, request_id, prompt, params, ...):
    # 1. 输入预处理：tokenize、处理多模态（图片等）
    request = self.input_processor.process_inputs(request_id, prompt, params, ...)
    # 2. 登记到输出处理器（后面用于 detokenize）
    self.output_processor.add_request(request, ...)
    # 3. 提交给核心引擎
    self.engine_core.add_request(request)
```

### step() —— 推进一步

```python
def step(self):
    # 1. 从核心引擎拿本轮输出
    outputs = self.engine_core.get_output()
    # 2. 后处理：detokenize（token → 文本）、判断是否该停止
    processed = self.output_processor.process_outputs(outputs.outputs, ...)
    # 3. 中止那些因停止词而完成的请求
    self.engine_core.abort_requests(processed.reqs_to_abort)
    return processed.request_outputs
```

## EngineCore：核心循环

这是整个 vLLM 最关键的方法。`core.py` 第 479 行：

```python
def step(self):
    # 没有请求就直接返回
    if not self.scheduler.has_requests():
        return {}, False

    # ① 调度：决定本轮处理哪些请求
    scheduler_output = self.scheduler.schedule()

    # ② 执行：交给 GPU 跑模型 forward
    future = self.model_executor.execute_model(scheduler_output, non_block=True)
    model_output = future.result()
    if model_output is None:
        # ③ 采样：从 logits 选出下一个 token
        model_output = self.model_executor.sample_tokens(grammar_output)

    # ④ 更新状态：标记完成的请求、更新进度
    engine_core_outputs = self.scheduler.update_from_output(
        scheduler_output, model_output
    )
    return engine_core_outputs
```

记住这**四步循环**，它是理解 vLLM 的钥匙：

```
① schedule   决定干什么   → 见 03-调度器.md
② execute    GPU 跑模型   → 见 05-Worker模型执行.md
③ sample     选下个 token → 见 06-采样.md
④ update     更新状态
```

每调用一次 `step()`，所有运行中的请求各自前进一个 token（decode 阶段），或一批 prompt token（prefill 阶段）。

## 为什么要拆成 LLMEngine 和 EngineCore

主要为了**多进程**。`EngineCore` 通常运行在独立进程里，专注于 GPU 计算；`LLMEngine` 在主进程里，处理 tokenize、detokenize 这些 CPU 工作。两者通过进程间通信（IPC）交换数据。

这样设计的好处：CPU 上的文本处理不会阻塞 GPU 计算，提升整体吞吐。`core.py` 里那些 `EngineCoreProc`、`DPEngineCoreProc` 就是处理多进程/分布式的封装。

## 初始化时发生了什么

`EngineCore.__init__`（`core.py` 第 99 行）按顺序创建了核心组件：

```python
self.model_executor = executor_class(vllm_config)        # 模型执行器（GPU worker）
kv_cache_config = self._initialize_kv_caches(vllm_config) # 探测可用显存，规划 KV Cache
self.scheduler = Scheduler(...)                           # 调度器
```

> `_initialize_kv_caches` 会先跑一次"试运行"，测出 GPU 还剩多少显存，然后据此决定 KV Cache 能切成多少个 block。这个数字直接决定了能并发多少请求。

## 小结

- 引擎是大脑，分两层：`LLMEngine`（对外）+ `EngineCore`（核心循环）
- 核心是 `EngineCore.step()` 的四步：调度 → 执行 → 采样 → 更新
- 拆两层 + 多进程，是为了让 CPU 处理不阻塞 GPU 计算
