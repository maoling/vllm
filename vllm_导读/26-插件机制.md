# 26 · 插件机制 (Plugins)

> 对应目录：`vllm/plugins/`

## 这个模块负责什么

让第三方在**不修改 vLLM 源码**的情况下，扩展或定制 vLLM 的行为。

类比 Web 后端：像 Spring 的扩展点、或 IDE 的插件系统——核心保持稳定，能力通过插件注入。

## 为什么需要插件

vLLM 是通用框架，但总有定制需求：

- 公司内部有自研模型，想接进来但不方便提交到主仓库
- 想加自定义的硬件平台
- 想注入特殊的输入/输出处理逻辑
- 想加自定义的 LoRA 解析方式

如果什么都改源码，升级 vLLM 时就要不停合并冲突。插件机制让定制和核心解耦。

## 工作原理：Python entry points

vLLM 用 Python 标准的 **entry points** 机制发现插件。你写一个独立的 Python 包，在它的 `pyproject.toml` 里声明：

```toml
[project.entry-points."vllm.general_plugins"]
my_plugin = "my_package:register"
```

vLLM 启动时会自动扫描所有注册到 `vllm.*` 这些 entry point 组的包，调用它们的注册函数。

回顾 `02-引擎.md` 的 `EngineCore.__init__`，第一行就是：

```python
from vllm.plugins import load_general_plugins
load_general_plugins()   # 加载所有通用插件
```

## 插件能做什么（常见类型）

| 插件类型 | 用途 | 目录 |
|----------|------|------|
| 通用插件 (general) | 注册自定义模型、平台等 | `plugins/__init__.py` |
| IO 处理器 (io_processors) | 自定义输入/输出处理 | `plugins/io_processors/` |
| LoRA 解析器 (lora_resolvers) | 自定义 LoRA 的发现/加载 | `plugins/lora_resolvers/` |

最常见的用法：**注册自定义模型**。结合 `14-模型加载与定义.md`，你可以在插件里把自己的模型类注册进模型注册表，vLLM 就能像用内置模型一样用它。

```python
# 在你的插件包里
def register():
    from vllm import ModelRegistry
    ModelRegistry.register_model("MyCustomModel", MyCustomModelClass)
```

## 插件 vs 直接贡献代码

| 方式 | 适用场景 |
|------|----------|
| 写插件 | 私有模型、公司内部定制、实验性功能、不想/不能开源 |
| 提 PR 进主仓库 | 通用功能、希望社区共享和维护（见 `13`、`14` 的贡献指引） |

## 对新手的意义

- 大多数使用场景用不到，了解"有这么个扩展机制"即可
- 如果你要接一个**没被 vLLM 支持的私有模型**，插件是不动源码的最优雅方式
- 它体现了好框架的设计：核心稳定 + 扩展点开放

## 小结

- 插件机制让第三方不改源码就能扩展 vLLM
- 基于 Python entry points，启动时自动发现加载
- 最常见用途：注册自定义模型；也支持 IO 处理、LoRA 解析等
- 定制私有功能用插件，通用功能走 PR 贡献
