# 14 · 模型加载与定义

> 对应目录：`vllm/model_executor/models/`、`vllm/model_executor/model_loader/`

## 这个模块负责什么

两件事：

1. **模型定义**：用代码描述每种模型的结构（有几层、每层怎么算）
2. **模型加载**：把硬盘上的权重文件读进来，填到模型结构里

类比 Web 后端：模型定义像"数据库表结构（schema）"，模型加载像"把数据导入表里"。

## 一、模型定义

### vLLM 为什么要自己定义模型

HuggingFace 上有现成的模型代码，但那是为"训练/通用推理"写的，没有针对 vLLM 的高吞吐场景优化。vLLM 重新实现一遍，为的是：

- 用 vLLM 自己的高性能层（PagedAttention、张量并行的线性层等）
- 适配连续批处理、KV Cache 分页等机制

### 代码结构

`model_executor/models/` 下每种模型一个文件：

```
models/
├── llama.py       ← Llama 系列
├── qwen2.py       ← Qwen2 系列
├── gpt2.py        ← GPT-2
├── llava.py       ← LLaVA（多模态）
├── registry.py    ← 模型注册表：模型名 → 实现类
└── ...            ← 几百个模型
```

### 一个模型定义长什么样

以 Llama 为例，结构大致是：

```python
class LlamaForCausalLM(nn.Module):
    def __init__(self, vllm_config):
        self.model = LlamaModel(...)        # 主体：一堆 Transformer 层
        self.lm_head = ...                  # 输出头：hidden → logits

    def forward(self, input_ids, positions, ...):
        hidden_states = self.model(input_ids, positions, ...)
        return hidden_states

    def compute_logits(self, hidden_states):
        return self.lm_head(hidden_states)  # 算每个词的分数
```

里面的 `LlamaModel` 又由多个 `LlamaDecoderLayer` 堆叠而成，每层包含注意力 + FFN。这些层用的都是 `model_executor/layers/` 里 vLLM 优化过的版本（见 `05-Worker模型执行.md`）。

### 模型注册表

`models/registry.py` 维护一个映射：模型架构名 → 实现类。

```
"LlamaForCausalLM"  → llama.py 里的类
"Qwen2ForCausalLM"  → qwen2.py 里的类
```

加载模型时，vLLM 读取模型配置文件（HuggingFace 的 `config.json`）里的 `architectures` 字段，去注册表里找对应的实现类。**给 vLLM 加新模型支持，本质就是写一个新的模型文件 + 在这里注册。**

## 二、模型加载

### 流程

```
模型路径（本地或 HuggingFace Hub）
  ↓
读 config.json → 知道是什么模型、多大
  ↓
查注册表 → 找到对应实现类，创建模型骨架（此时权重是空的）
  ↓
读权重文件（.safetensors / .bin）
  ↓
把权重填进模型，按需切分到多卡（张量并行）
  ↓
就绪
```

### 代码结构

| 文件/目录 | 作用 |
|-----------|------|
| `model_loader/__init__.py` | 加载入口 |
| `model_loader/default_loader.py` | 默认加载器 |
| `model_loader/weight_utils.py` | 权重读取、格式转换工具 |

### 权重格式

主流是 `.safetensors`（安全、加载快，现在的标准），老格式是 PyTorch 的 `.bin`。加载器会处理不同格式，还会处理量化权重的特殊打包格式（见 `09-量化.md`）。

### 多卡加载的巧思

张量并行时，每张卡只需要权重的一部分。加载器会**只把对应分片读到每张卡**，而不是每张卡都读全量再切——这样省内存也更快。

## 怎么给 vLLM 加一个新模型（贡献入口）

这是热门的新手贡献方向，大致步骤：

1. 在 `models/` 下新建模型文件，参考结构最接近的已有模型
2. 用 vLLM 的层实现模型结构
3. 实现权重加载逻辑（把 HuggingFace 权重名映射到你的层）
4. 在 `registry.py` 注册
5. 写测试（见 `docs/contributing/model/`）

## 小结

- 模型定义：用 vLLM 的高性能层重新描述模型结构，在 `models/`
- 模型加载：读配置 → 建骨架 → 填权重 → 切分到多卡
- 注册表把"模型名"映射到"实现类"
- 加新模型 = 写新模型文件 + 注册，是友好的贡献方向
