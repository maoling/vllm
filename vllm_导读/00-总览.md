# vLLM 核心模块导读 · 总览

> 写给新手小白的 vLLM 源码导读。假设你会一点 Python，了解后端开发概念（请求、队列、内存管理），但不熟悉深度学习底层。

## vLLM 是什么

一句话：**一个高性能的大语言模型（LLM）推理引擎**。

你给它一个 prompt（提示词），它高效地调用 GPU 上的大模型，生成回答。它的核心价值是**高吞吐**——同一块 GPU 能同时服务尽可能多的请求。

## 核心创新：PagedAttention

vLLM 出名的原因是 PagedAttention。简单说：

- 大模型生成时需要缓存中间结果（叫 KV Cache），占用大量显存。
- 传统做法：给每个请求预留一大块连续显存，浪费严重。
- vLLM 做法：像操作系统管理内存页一样，把显存切成固定大小的小块（block），按需分配。

结果：显存利用率大幅提升，能塞下更多并发请求，吞吐量提高数倍。

## 用什么语言写的

| 语言 | 用途 | 占比 |
|------|------|------|
| Python | 框架主体：调度、引擎、API、模型定义 | 大部分 |
| C++/CUDA | 高性能计算 kernel（attention、量化等） | 性能关键路径 |
| Rust | 实验性高性能前端（tokenizer 等） | 补充 |

**Python 不会拖慢性能**：因为 95% 以上的时间花在 GPU 计算上，Python 只负责"管理调度"，有充足时间在 GPU 计算的空隙里完成工作。这和 PyTorch 一样——Python 写接口，C++/CUDA 做计算。

## 用 Web 后端思维类比

如果你是后端开发，可以这样理解 vLLM（以 Java Tomcat 为例）：

| Web 容器 (Tomcat) | vLLM 对应 |
|-------------------|-----------|
| HTTP Connector | `entrypoints/`（API 服务器） |
| Servlet Container | `LLMEngine`（引擎） |
| 请求队列 + 线程调度 | `Scheduler`（调度器） |
| JVM 堆内存管理 | `KVCacheManager`（显存块管理） |
| 工作线程 | GPU Worker（模型执行） |
| Response Writer | OutputProcessor（输出处理） |

**最大区别**：Tomcat 是"一个请求一个线程"，互不干扰；vLLM 是"所有请求共享一块 GPU"，每一步同时推进一批请求（batching）。这就是调度器复杂的根本原因。

## 核心模块地图

```
用户请求
   │
   ▼
① 入口层 (Entrypoints)        ← 见 01-入口层.md
   │   接收请求、tokenize
   ▼
② 引擎 (Engine)               ← 见 02-引擎.md
   │   协调全局、主循环
   ▼
③ 调度器 (Scheduler)          ← 见 03-调度器.md
   │   决定本轮处理哪些请求
   ▼
④ KV Cache 管理               ← 见 04-KVCache管理.md
   │   分配/回收显存块 (PagedAttention)
   ▼
⑤ Worker / 模型执行           ← 见 05-Worker模型执行.md
   │   GPU 上跑模型 forward
   ▼
⑥ 采样 (Sampling)             ← 见 06-采样.md
   │   从概率分布选出下一个 token
   ▼
返回结果
```

完整的请求生命周期串讲见 `07-请求生命周期.md`。
