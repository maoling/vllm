# 22 · 性能指标与基准测试 (Metrics & Benchmarks)

> 对应目录：`vllm/v1/metrics/`、`benchmarks/`、`vllm/benchmarks/`

## 这个模块负责什么

两件事：

1. **运行时指标 (Metrics)**：服务跑起来后，实时监控吞吐、延迟、显存等
2. **基准测试 (Benchmarks)**：离线压测，衡量某个配置/版本的性能

类比 Web 后端：Metrics 像 Prometheus 监控埋点，Benchmarks 像 JMeter 压测。

## 一、关键性能指标

理解 LLM 服务性能，先记住这几个核心指标：

| 指标 | 全称 | 含义 | 直觉 |
|------|------|------|------|
| TTFT | Time To First Token | 首 token 延迟 | 从发请求到吐出第一个字多久（主要受 prefill 影响） |
| TPOT | Time Per Output Token | 每个输出 token 的耗时 | 后续吐字的速度（decode 速度） |
| ITL | Inter-Token Latency | token 间隔延迟 | 和 TPOT 类似，逐 token 的间隔 |
| Throughput | 吞吐量 | 每秒处理的 token / 请求数 | 系统整体产能 |
| Latency | 延迟 | 单个请求的总耗时 | 用户等待时间 |

### 吞吐 vs 延迟的权衡

这是 LLM 服务的核心矛盾：

- 想要**高吞吐**：把更多请求塞进一个 batch（batch 越大，GPU 利用率越高）
- 想要**低延迟**：batch 小一点，单个请求更快响应

vLLM 的调度器（见 `03`）就是在不断平衡这两者。`gpu_memory_utilization`、`max_num_seqs` 等配置（见 `19`）直接影响这个权衡。

## 二、运行时指标采集

代码在 `vllm/v1/metrics/`。引擎每步（`step()`）会更新统计：

- 调度器统计：running/waiting 请求数、KV Cache 使用率、抢占次数
- 迭代统计：本步处理的 token 数、prefill/decode token 数

回顾 `02-引擎.md` 的 `LLMEngine.step()`，第 4 步 "record stats" 就是在记录这些。

### Prometheus 集成

在线服务（`vllm serve`）会暴露一个 `/metrics` 端点，输出 Prometheus 格式的指标，可以接到 Grafana 做监控大盘。这是生产部署的标配。

```
GET /metrics
→ vllm:num_requests_running 12
  vllm:gpu_cache_usage_perc 0.87
  vllm:time_to_first_token_seconds ...
  ...
```

## 三、基准测试工具

`benchmarks/` 目录提供压测脚本：

| 脚本 | 用途 |
|------|------|
| `benchmark_throughput.py` | 离线吞吐测试（一次性灌大量请求，看总吞吐） |
| `benchmark_latency.py` | 延迟测试（单请求/小批量的响应时间） |
| `benchmark_serving.py` | 在线服务压测（模拟真实流量，测 TTFT/TPOT 等） |

也可以通过 CLI 使用（`vllm/benchmarks/`）：

```bash
vllm bench throughput --model meta-llama/Llama-3-8B --num-prompts 1000
vllm bench serving --model meta-llama/Llama-3-8B ...
```

### 压测能回答的问题

- 换个配置（TP 大小、量化方法）性能差多少？
- 我的卡能扛多少 QPS？
- 改了代码有没有性能回退？（CI 里就用基准测试防止性能退化）

## 对新手的意义

- 想评估"某个改动有没有用"，跑 benchmark 用数据说话
- 看懂 TTFT/TPOT/吞吐这几个词，就能读懂 vLLM 的性能讨论和 release notes
- 性能调优本质就是在监控指标的指导下，调 `19-配置系统.md` 里的旋钮

## 小结

- 核心指标：TTFT（首字延迟）、TPOT（吐字速度）、吞吐、延迟
- 核心矛盾：高吞吐（大 batch）vs 低延迟（小 batch），调度器在平衡
- 运行时指标经 `/metrics` 暴露给 Prometheus，做生产监控
- `benchmarks/` 提供吞吐/延迟/在线压测脚本，用数据驱动调优
