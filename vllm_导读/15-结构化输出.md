# 15 · 结构化输出 (Structured Output)

> 对应目录：`vllm/v1/structured_output/`

## 要解决的问题

很多场景需要模型输出**严格符合某种格式**，比如：

- 必须是合法的 JSON
- 必须匹配某个正则表达式
- 必须从给定的几个选项里选一个
- 必须符合某个 JSON Schema

但模型是"概率生成"的，它可能吐出格式错误的内容（比如 JSON 少个引号）。结构化输出就是**强制保证**生成的内容一定合法。

类比：给模型套上"轨道"，它只能在合法的路径上走，没法跑偏。

## 核心思想：约束采样

回顾 `06-采样.md`：每一步模型对词表里每个 token 给一个分数（logits），然后采样。

结构化输出的做法是：**在采样前，把所有"会导致格式非法"的 token 分数压到负无穷**，这样它们绝不可能被选中。

```
正常采样：从所有 token 里选
结构化采样：只从"此刻合法的 token"里选
```

### 举个例子

假设要求输出 JSON，当前已经生成了 `{"name"`，那么下一个合法的 token 只能是 `:`。结构化输出就会把除了 `:` 之外的所有 token 屏蔽掉，模型只能输出 `:`。

## 关键机制：语法掩码 (Grammar Bitmask)

实现靠一个"掩码"——一个和词表等长的布尔数组，标记每个 token 此刻是否合法：

```
词表:   [ "a",  ":",  "}",  "1",  ... ]
掩码:   [  0,    1,    0,    0,   ... ]   ← 只有 ":" 合法
```

把掩码应用到 logits 上（非法位置设为负无穷），再采样。

回顾 `02-引擎.md` 的 `EngineCore.step()`，里面有一行：

```python
grammar_output = self.scheduler.get_grammar_bitmask(scheduler_output)
```

这就是在为本轮需要结构化输出的请求计算掩码。

## 状态机驱动

合法的 token 随生成进度变化（生成 `{` 后、生成 `"key"` 后……合法集合都不同）。所以底层维护一个**状态机**：

```
当前状态 + 已生成的 token → 推进状态 → 算出下一步合法的 token 集合
```

vLLM 通常借助专门的库（如 XGrammar、Outlines）来高效维护这个状态机和生成掩码。

## 代码结构

| 文件/目录 | 作用 |
|-----------|------|
| `v1/structured_output/__init__.py` | `StructuredOutputManager`，总管 |
| `v1/structured_output/backend_*.py` | 不同后端（xgrammar 等）的接入 |

`StructuredOutputManager` 在引擎初始化时创建（见 `core.py` 的 `__init__`），负责为每个带格式约束的请求维护状态机、生成掩码。

## 怎么用

```python
from vllm import LLM, SamplingParams
from vllm.sampling_params import GuidedDecodingParams

llm = LLM(model="meta-llama/Llama-3-8B")

guided = GuidedDecodingParams(json={"type": "object", "properties": {...}})
params = SamplingParams(guided_decoding=guided)

outputs = llm.generate("生成一个用户信息", params)
# 输出保证是符合 schema 的合法 JSON
```

支持的约束类型：JSON Schema、正则表达式、选项列表（choice）、上下文无关文法（grammar）。

## 性能考量

生成掩码有开销（要跑状态机），但通常远小于模型 forward，所以对整体速度影响不大。vLLM 还会异步计算掩码，尽量和 GPU 计算重叠。

## 小结

- 结构化输出 = 强制模型生成合法格式（JSON、正则等）
- 原理：采样前用"语法掩码"屏蔽所有会导致非法的 token
- 靠状态机跟踪进度，动态算出每步合法的 token 集合
- 由 `StructuredOutputManager` 统管，可对接 xgrammar 等后端
