# 29 · 命令行工具 (CLI)

> 对应目录：`vllm/entrypoints/cli/`

## 这个模块负责什么

提供 `vllm` 命令行工具，让你不用写 Python 就能启动服务、压测、batch 推理等。这是大多数用户接触 vLLM 的第一个入口。

类比 Web 后端：像 `mvn`、`npm`、`kubectl` 这样的命令行入口。

## 主要子命令

| 命令 | 作用 | 对应文件 |
|------|------|----------|
| `vllm serve <model>` | 启动 OpenAI 兼容的 HTTP 服务（最常用） | `cli/serve.py` |
| `vllm bench <type>` | 跑基准测试（throughput/latency/serving） | `cli/benchmark/` |
| `vllm run-batch` | 批量离线推理（读输入文件，批量处理） | `cli/run_batch.py` |
| `vllm collect-env` | 收集环境信息（排查问题时贴给 issue） | `cli/collect_env.py` |
| `vllm chat` / `complete` | 命令行里直接和模型对话 | `cli/openai.py` |

## 入口与分发

`cli/main.py` 是总入口，把命令分发到各子命令。安装 vLLM 时，`vllm` 这个命令通过 `pyproject.toml` 的 entry point 注册到系统：

```toml
[project.scripts]
vllm = "vllm.entrypoints.cli.main:main"
```

所以 `pip install vllm` 后就有了 `vllm` 命令。

## 最常用：vllm serve

```bash
vllm serve meta-llama/Llama-3-8B \
    --tensor-parallel-size 2 \
    --max-model-len 4096 \
    --port 8000
```

这条命令背后（呼应 `23-OpenAI兼容API服务.md`）：

```
解析命令行参数（cli/serve.py + cli_args.py）
  ↓ 转成 EngineArgs → VllmConfig（见 19-配置系统）
  ↓ 构建引擎 + FastAPI 应用（api_server.py）
  ↓ 启动 uvicorn 服务器，监听端口
就绪，开始接收 HTTP 请求
```

## 参数从哪来

命令行的一大堆 `--xxx` 参数，定义在 `engine/arg_utils.py`（`EngineArgs`）和 `openai/cli_args.py`。它们和 `19-配置系统.md` 的 `VllmConfig` 一一对应——命令行参数就是配置对象的"文本形式"。

想知道某个参数干什么：

```bash
vllm serve --help
```

## 对新手的意义

- 你的 vLLM 之旅大概率从 `vllm serve` 开始
- 看懂 CLI = 知道怎么把前面所有模块"跑起来"
- 调参（`--tensor-parallel-size`、`--gpu-memory-utilization` 等）就是在这里指定配置（见 `19`）

## 小结

- CLI 提供 `vllm` 命令：serve（起服务）、bench（压测）、run-batch（批量）等
- `cli/main.py` 分发子命令，通过 entry point 注册为系统命令
- `vllm serve` 是最常用入口，背后是"解析参数 → 配置 → 引擎 → HTTP 服务"
- 命令行参数对应 `19-配置系统.md` 的 VllmConfig
