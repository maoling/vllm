# 40 · 并行采样与多候选 (Parallel Sampling)

> 对应文件：`vllm/v1/engine/parallel_sampling.py`

## 要解决的问题

有时一个 prompt 你想要**多个不同的回答**。比如：

- 让模型对同一问题生成 5 个候选，挑最好的
- 创意写作，要几个不同版本
- 采样多条做投票（self-consistency）

这就是 `SamplingParams` 里的 `n` 参数：

```python
SamplingParams(n=5)   # 同一个 prompt 生成 5 个独立回答
```

## vLLM 怎么实现

朴素想法是把同一个 prompt 复制 5 份当 5 个请求。vLLM 做得更聪明：**共享 prompt 的计算**。

回顾 `02-引擎.md` 的 `LLMEngine.add_request`，当 `n > 1` 时：

```python
# Fan out child requests (for n>1).
parent_req = ParentRequest(request)
for idx in range(n):
    child_request = ...           # 创建 n 个子请求
    self.engine_core.add_request(child_request)
```

一个"父请求"展开成 n 个"子请求"。关键优化：这 n 个子请求**共享同一个 prompt 的 KV Cache**（靠前缀缓存，见 `16`）——prompt 只算一次，n 个分支从这里各自分叉生成。

```
prompt "写首诗"（KV Cache 只算一次，n 个分支共享）
  ├─ 子请求1 → "春风拂面..."
  ├─ 子请求2 → "明月当空..."
  └─ 子请求3 → "细雨绵绵..."
```

## ParentRequest：管理父子关系

`parallel_sampling.py` 里的 `ParentRequest` 负责：

- 把父请求展开成 n 个子请求
- 收集 n 个子请求的输出
- 合并成一个结果返回给用户（用户视角还是"一个请求，n 个输出"）

```
用户看到：
RequestOutput(
    outputs=[
        CompletionOutput(text="春风拂面..."),   # n=0
        CompletionOutput(text="明月当空..."),   # n=1
        CompletionOutput(text="细雨绵绵..."),   # n=2
    ]
)
```

## 和 Beam Search 的区别

容易混淆两个"多候选"概念：

| | 并行采样 (n>1) | Beam Search |
|---|---|---|
| 怎么生成 | n 个分支各自独立随机采样 | 维护 top-k 条最优路径，每步剪枝 |
| 分支间 | 互不影响 | 互相竞争，动态淘汰 |
| 用途 | 要多样化的候选 | 要"整体概率最高"的序列 |

vLLM 主要优化并行采样；beam search 也支持但用得较少（很多生成任务更偏好采样）。

## 调度视角

这 n 个子请求对调度器（`03`）来说就是普通请求，一起参与 batch、各自占 KV Cache 块。所以 `n=5` 大致相当于多了几个并发请求的负载（但省了 prompt 的重复计算）。

## 怎么用

```python
outputs = llm.generate("写一句励志的话", SamplingParams(n=3, temperature=0.9))
for o in outputs[0].outputs:   # 遍历 3 个候选
    print(o.text)
```

> 提示：`n>1` 配合较高的 `temperature` 才有意义——温度太低，几个候选会趋同。

## 小结

- `n>1` 让一个 prompt 生成多个候选回答
- vLLM 展开成 n 个子请求，但共享 prompt 的 KV Cache（只算一次）
- `ParentRequest` 管理父子关系，最后合并成一个结果返回
- 区别于 beam search：并行采样是独立分支，beam 是竞争剪枝
