# 06 · 采样 (Sampling)

> 对应目录：`vllm/v1/sample/`

## 这个模块负责什么

模型 forward 算出了 logits（每个候选 token 的分数），采样模块负责**从这些分数里选出真正的下一个 token**。

类比：模型给出"建议名单和打分"，采样器是"做最终决定的人"。

## 为什么需要采样，不直接选最高分

如果每次都选分数最高的 token（叫 greedy/贪心），模型输出会非常死板、重复。引入随机性能让输出更自然、有创造力。控制这个随机性的参数就是大家熟悉的 `temperature`、`top_p` 等。

## 关键参数（SamplingParams）

这些参数用户在请求里指定，定义在 `vllm/sampling_params.py`：

| 参数 | 作用 | 直觉理解 |
|------|------|----------|
| `temperature` | 温度，控制随机性 | 越高越随机有创意，越低越确定保守；0 = 贪心 |
| `top_p` | 核采样 | 只从累计概率前 p 的词里选（比如前 90%） |
| `top_k` | 只从分数最高的 k 个词里选 | k 越小越保守 |
| `max_tokens` | 最多生成多少 token | 输出长度上限 |
| `stop` | 停止词 | 遇到就停止生成 |
| `presence_penalty` | 出现惩罚 | 降低已出现过的词的概率，减少重复 |
| `frequency_penalty` | 频率惩罚 | 出现越多次，惩罚越重 |

## 采样流程

拿到 logits 后，大致按这个顺序加工：

```
原始 logits（每个 token 的分数）
  ↓
① 应用 penalties（重复惩罚、频率惩罚）
  ↓
② 除以 temperature（温度缩放，调整随机程度）
  ↓
③ top-k / top-p 过滤（砍掉不太可能的词）
  ↓
④ softmax 转成概率分布
  ↓
⑤ 按概率随机采样（或 temperature=0 时直接取最大）
  ↓
得到下一个 token id
```

## 关键文件

| 文件 | 作用 |
|------|------|
| `sample/metadata.py` | `SamplingMetadata`，打包一个批次的采样参数 |
| `sample/ops/penalties.py` | 各种惩罚的实现 |
| `sample/ops/bad_words.py` | 禁用词处理 |
| `sample/logits_processor/` | logits 处理器（可插拔的加工步骤） |

## Logits Processor：可插拔的加工

`sample/logits_processor/` 是一个可扩展机制。每个 processor 在采样前对 logits 做一次加工，比如：

- `MinPLogitsProcessor`：min-p 采样
- 自定义处理器：用户甚至能插入自己的逻辑（比如强制某些词不出现）

这是一个"责任链"模式：logits 依次流过每个 processor。

## 批处理：一次给一批请求采样

别忘了 vLLM 是 batch 处理的。采样不是一次处理一个请求，而是**同时给整个 batch 的所有请求各采样一个 token**。`SamplingMetadata` 就是把这一批请求各自的采样参数打包到一起，让 GPU 一次性并行处理。

## 结构化输出（顺带一提）

代码里有 `grammar_output`、`structured_output`。这是一个高级特性：强制模型输出符合某种格式（比如合法的 JSON）。原理是在采样时用一个"语法掩码"（grammar bitmask）把不符合格式的 token 分数压到负无穷，让它们不可能被选中。相关代码在 `vllm/v1/structured_output/`。

## 小结

- 采样 = 从 logits（候选分数）里选出实际的下一个 token
- 通过 temperature、top_p、top_k 等参数控制随机性和质量
- 流程：惩罚 → 温度缩放 → top-k/p 过滤 → softmax → 采样
- 一次给整个 batch 并行采样
- 选出的 token 会拼回请求，下一步继续生成，直到遇到停止条件
