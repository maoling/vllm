# 36 · 环境变量与运行时开关

> 对应文件：`vllm/envs.py`

## 这个模块负责什么

集中管理 vLLM 的**环境变量**——那些用 `VLLM_XXX` 形式控制行为的开关。`envs.py` 是它们的唯一定义处。

类比 Web 后端：像 12-factor app 里的环境变量配置，区别于 `19-配置系统.md` 那种"每次请求/启动传的参数"，环境变量更偏向"部署环境/底层行为"的全局开关。

## 配置 vs 环境变量：怎么区分

| | 配置（VllmConfig，见 19） | 环境变量（envs.py） |
|---|---|---|
| 控制什么 | 模型、并行、调度等业务参数 | 底层行为、调试开关、后端选择 |
| 怎么传 | 命令行 `--xxx` / Python 参数 | `export VLLM_XXX=...` |
| 典型例子 | `--tensor-parallel-size` | `VLLM_LOGGING_LEVEL` |

简单说：配置是"这次要怎么跑"，环境变量是"这台机器/这个环境的底层设定"。

## envs.py 的写法

`envs.py` 用一个字典集中定义所有环境变量，每个都带默认值和读取逻辑：

```python
environment_variables = {
    # 日志级别
    "VLLM_LOGGING_LEVEL": lambda: os.getenv("VLLM_LOGGING_LEVEL", "INFO"),
    # 是否用预编译版本（见 AGENTS.md 安装说明）
    "VLLM_USE_PRECOMPILED": lambda: bool(os.getenv("VLLM_USE_PRECOMPILED")),
    # ... 几百个开关
}
```

代码里通过 `import vllm.envs as envs; envs.VLLM_XXX` 来读取。集中管理的好处：所有开关一目了然，有统一的默认值和类型处理。

## 一些常见的环境变量

> 这里只举例帮助理解类别，具体以 `envs.py` 为准。

| 类别 | 例子 | 作用 |
|------|------|------|
| 日志/调试 | `VLLM_LOGGING_LEVEL` | 日志详细程度（见 `31`） |
| 安装/编译 | `VLLM_USE_PRECOMPILED` | 装预编译版本，跳过 C++ 编译（见 `21`） |
| 后端选择 | `VLLM_ATTENTION_BACKEND` | 强制指定注意力后端（见 `28`） |
| 缓存路径 | `VLLM_CACHE_ROOT` | 缓存文件存哪 |
| 多模态 | `VLLM_IMAGE_FETCH_TIMEOUT` | 拉取图片的超时 |
| 实验开关 | 各种 `VLLM_ENABLE_XXX` | 开启/关闭实验特性 |

查看所有可用变量，直接读 `vllm/envs.py` 里的字典（注释通常说明了用途）。

## 为什么单独了解

- **排查问题**：很多"诡异行为"是某个环境变量导致的，知道去 `envs.py` 查
- **调试**：调高日志级别、强制某个后端，常靠环境变量
- **部署**：CI/Docker 里常通过环境变量定制行为
- **读源码**：看到 `envs.VLLM_XXX` 就知道这是个全局开关，去 `envs.py` 查含义

## 和命令行参数的配合

实际部署常两者并用：

```bash
export VLLM_LOGGING_LEVEL=DEBUG          # 环境变量：调试日志
export VLLM_ATTENTION_BACKEND=FLASHINFER # 环境变量：指定后端
vllm serve meta-llama/Llama-3-8B \        # 命令行参数：业务配置
    --tensor-parallel-size 2
```

## 对新手的意义

- 平时默认值就够用，不用动
- 遇到问题或想调试时，知道"有 `envs.py` 这么个全局开关清单"很有用
- 是阅读源码、排查环境问题的一把钥匙

## 小结

- `envs.py` 集中定义所有 `VLLM_XXX` 环境变量
- 环境变量管"底层行为/环境设定"，配置管"业务参数"，两者互补
- 常见用途：日志级别、编译方式、后端选择、缓存路径、实验开关
- 排查诡异问题、调试、部署定制时的重要钥匙
