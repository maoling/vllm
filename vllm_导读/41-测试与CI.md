# 41 · 测试与持续集成 (Testing & CI)

> 对应目录：`tests/`、`.buildkite/`、`.github/`

## 为什么单独讲

如果你想给 vLLM 贡献代码（呼应之前聊的"如何贡献"），就绕不开测试和 CI。这章帮你理解项目怎么保证质量，以及你的 PR 会经历什么。

## 测试目录结构

`tests/` 按模块组织，结构大致对应 `vllm/`：

| 目录（示例） | 测什么 |
|------|--------|
| `tests/kernels/` | CUDA/算子的正确性 |
| `tests/models/` | 各模型能否正确加载和推理 |
| `tests/entrypoints/` | API、LLM 类等入口 |
| `tests/v1/` | v1 引擎、调度器、KV Cache 等核心 |
| `tests/lora/` | LoRA 功能 |
| `tests/multimodal/` | 多模态 |
| `tests/distributed/` | 分布式/并行 |

## 用什么测：pytest

vLLM 用 `pytest`。运行单个测试文件（参考 `AGENTS.md`）：

```bash
# 注意：项目要求用 uv 和 .venv，不要用系统 python
.venv/bin/python -m pytest tests/path/to/test_file.py -v
```

测试分几类：

- **单元测试**：测单个函数/类（快，无需 GPU 的居多）
- **集成测试**：测多个模块协作（如端到端推理）
- **正确性测试**：比如算子结果和参考实现对比，模型输出质量评估

## kernel 测试的特殊性

回顾 `21-自定义算子与CUDA内核.md`，自定义算子要用 PyTorch 的机制验证：

```python
torch.library.opcheck(...)   # 检查算子注册、meta-function 是否正确
```

`CONTRIBUTING.md` 明确要求：改 kernel 要用 `opcheck` 测，`tests/kernels/` 有大量例子。

## 持续集成 (CI)：.buildkite

`.buildkite/` 是 vLLM 的 CI 配置（用 Buildkite 平台）。你提 PR 后，CI 会自动在各种硬件上跑测试：

```
.buildkite/
├── test-pipeline.yaml      ← 定义跑哪些测试
├── hardware_tests/         ← 不同硬件的测试（amd/cpu/intel/gh200...）
├── lm-eval-harness/        ← 模型质量评估（跑标准数据集看准确率）
└── performance-benchmarks/ ← 性能基准（防止性能回退，见 22）
```

CI 在真实 GPU（甚至多种厂商的卡）上跑，因为很多问题只在特定硬件上才暴露。

## 代码质量检查：pre-commit

提交前的格式/静态检查用 `pre-commit`（参考 `AGENTS.md`）：

```bash
pre-commit run --all-files       # 跑所有检查
pre-commit run ruff-check        # 单个：ruff（lint）
pre-commit run mypy-3.12 ...     # 类型检查
```

包含：ruff（代码风格 + lint）、mypy（类型检查）、格式化等。Python 行宽限制 88 字符。

## 你的 PR 会经历什么

```
你提交 PR
  ↓ pre-commit 检查（本地就该先跑）
  ↓ CI 自动触发：lint → 单元测试 → 集成测试 → （可能）多硬件测试
  ↓ reviewer 审查代码
  ↓ 加 ready 标签触发完整 CI
  ↓ 通过 → 合并
```

> `CONTRIBUTING.md` 提到：因算力有限，不是每次都跑全量 CI，reviewer 会按需触发。

## 对新手的意义

- 贡献代码前，本地一定要跑 `pre-commit` 和相关测试（AGENTS.md 强调"人必须跑过测试"）
- 写新功能要配套写测试（这是 PR 被接受的硬要求）
- 看 `tests/` 里的现有测试，是学习"某个功能怎么用"的好途径——测试就是可运行的示例

## 小结

- `tests/` 按模块组织，用 pytest 跑；kernel 要用 opcheck 验证
- `.buildkite/` 是 CI，在多种真实硬件上自动跑测试 + 质量评估 + 性能基准
- `pre-commit` 做提交前的 lint/类型/格式检查（行宽 88）
- 贡献代码必须：本地跑测试 + 配套写测试，这是质量底线
